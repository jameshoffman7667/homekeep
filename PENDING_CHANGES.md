# Pending changes (not yet in a released version)

Ideas logged here since the last release. When you say "create a new version,"
all of these get implemented together, the version is bumped, and this file
is cleared back to empty.

Current release: v2.1

## Log

1. Left navigation bar always uses the light-mode (darker blue) colour, in both light and dark themes.
2. Alarms: add a location filter (like Work Orders, Assets, etc.); beside each location in the filter, show a red flashing beacon-light symbol when that location has an active alarm.
3. Rename "Alarm Dashboard" to just "Alarms" (nav, page title, docs, spec).
4. Load the expanded PM template lists (drafted after v2.1: ~143 home, ~163 facility entries) as the default catalogues per edition; extend the seed loader to honour the `category` field.
5. Work order comment rule: moving a WO from In Progress to Completed (Scheduled to Completed, after item 6) requires a comment. (Supersedes the earlier "closed requires a comment" note.)
6. Rename work order statuses: Open → **Active**, In Progress → **Scheduled**, Completed stays, Verified → **Closed**. Needs a data migration of stored statuses, Excel import accepting old and new names, and updates to filters, badges, dashboards, docs and spec.
7. Auto-move a WO from Active to Scheduled when a scheduled date is assigned. Clearing the scheduled date reverts it to Active. PM-generated WOs do NOT auto-move: the trigger is the scheduled date only, never the due/required date.
8. Bulk auto-schedule on the work order list: a checkbox in the corner of each work order, a select-all checkbox in the column header, and an "Auto schedule" button. Auto schedule sets each selected WO's scheduled date to its required date (which then moves it to Scheduled per item 7). Confirm at build: WOs with no required date are skipped and reported; WOs already Scheduled/Completed/Closed are left alone.
9. Required date becomes a required field on every work order type (PM, PM Base, Benchmark, Corrective, Unplanned, and work-request conversions). Existing work orders with no required date are backfilled to the date of the upgrade (today). Corrective and Unplanned work orders must have a date entered at creation, with no default.
10. PM Base "standby": a PM Base can be put on standby, which stops it generating new child work orders. Standby can be set manually, or driven by a yearly date range on the PM Base (e.g. weekly lawn mowing: active May 1, standby November 1, every year). Confirm at build: existing open children are left alone, and on reactivation missed occurrences are not backfilled (generation resumes from the next due date).
11. Purchasing screen: ability to manually add a part (not only parts already in the catalogue).
12. Link-based pre-population for assets, vendors and parts: paste a link and the form fields fill in from it, improved with AI via a Gemini API key. The key is an optional Docker environment variable (`GEMINI_API_KEY`, passed through `docker-compose.yml` and documented in `.env.example`), read server-side only, never sent to the browser, and only used if provided; without it, a plain page-metadata fallback is used. Every pre-populated field shows a semi-transparent "x" at its right side to clear that value. Build notes: server-side fetch needs SSRF protection and a timeout; page content is sent to Google when the AI option is on; add a feature flag/env so editions can turn it off.
13. Owner-managed settings replace env/fork editions (supersedes v2.1's env-only approach, so no separate fork or per-edition pending list is needed). New Owner Tools cards: "Branding & Terminology" (name, short name, tagline, logo upload, four colour pickers, six location-level labels, "site level" dropdown, household/organization word, "Apply Home preset" / "Apply Facilities preset" buttons) and "Features" (toggles for Home Assistant alarms and link pre-population; enforced per request, no restart). Saved settings override env; env vars (EDITION, BRAND_*, etc.) only supply first-run defaults. Stored in `app_settings`, included in the Excel backup as a Settings sheet plus Export/Import settings JSON. Logo upload is Owner-only, image types with a size cap, served as an image with nosniff. Contrast warning on colours and a "Reset to defaults" button. Secrets stay in env (Gemini key: show "detected yes/no" and a use toggle only). Optional later: generate PWA icons from the uploaded logo.
14. Location level labels editable by the Owner (part of item 13's Branding & Terminology card): six free-text fields, each required, trimmed and limited to 15 characters, with no fixed vocabulary. Labels are display-only over stable stored keys, so changing one updates every existing record's display instantly with no data rewrite (Locations tree, tags, dropdowns, help text, Excel export; Excel import accepts stored keys or any current label). Confirm at build: block duplicate labels.
15. Customizable title in the top bar (e.g. an organization or site name), set by the Owner in Owner Tools (Branding card), blank by default: when blank nothing extra is shown. Length-limited (about 40 characters).
